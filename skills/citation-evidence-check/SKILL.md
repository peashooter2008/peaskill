# 文献证据核验

把“来源真实存在”“原文支持这句话”“当前稿件已审核”分别核对。先保留稿件及资料快照，再检查引用；失败时交付原稿、证据和问题清单。

## 工作方式

1. **确定稿件边界。** 检查正文中的实质论断与引用，参考文献表另行核对。辅助脚本只处理单独的 `[1]`、`[2]` 标号；将 `[1–3]` 等组合展开后再使用，保持稿件表达不变。
2. **取得可核对的原文。** 核对作者、标题、年份、DOI 或来源地址；保存所用版本和取得时间。摘要、搜索摘要、未核实摘录或无法读清的扫描件应保留为待补证据。`full_text` 是操作者对资料完整性的声明，脚本不能证明下载材料是全文或来源可信。
3. **逐项绑定证据。** 每个引用绑定明确来源、逐字片段、定位和相邻上下文。PDF 先保留页内连续文字，再划分片段；保留页码及附近限制条件。写作和审核使用同一份证据快照，避免重新检索后换掉写作时依据。
4. **先检查结构。** 按 [清单格式与命令](references/manifest-format.md) 填写清单，运行辅助工具。核对未知标号、片段来源、原文一致性及内容摘要；处理报告中的问题，不静默删除不利证据。
5. **再独立核对语义。** 阅读每个论断及相邻原文，检查对象、时间、条件、统计意义和预印本状态。可由人或用户已有的模型服务审核；本技能不会调用模型。模型结论仍需保留限制，重要论断应人工核对。详细判断见 [审核要点](references/evidence-workflow.md)。
6. **记录当前审核并再次检查。** 明确通过后才记录审核者、时间、说明和本次 `fingerprint`。正文、来源元数据、原文或片段改变会使旧记录失效，必须重新审查。不要用脚本自动把 `pending` 改成 `passed`。

## 最小使用

依赖 Python 3.10+ 标准库，无额外包；可在任意工作目录运行，资料路径相对于清单文件。

```text
python <skill目录>/scripts/check_evidence_manifest.py --manifest <资料目录>/manifest.json --report <输出目录>/report.json
```

- `0`：结构检查通过，且显式语义审核与当前内容指纹一致。
- `1`：当前稿件被阻止，包括待语义审核；查看报告中的 `issues`。
- `2`：命令或输入输出错误。

`examples/manifest.json` 是完全虚构、待审核的样例，应返回 `1`；`examples/reviewed-manifest.json` 展示同一虚构材料的审核记录格式，应返回 `0`。完整命令见清单格式说明。

## 交付和适用边界

交付稿件、引用到来源的映射、可定位证据、问题清单和当前检查报告；说明哪些来源无法获得、哪些论断仍待核实。

`exportAllowed` 仅供业务程序读取。若用户要求严格导出限制，应由实际应用在复制和每个导出入口检查当前报告；本脚本不会修改剪贴板、拦截其他程序或认证审核者。即使值为 `true`，也只表示清单一致且存在匹配的审核记录，不能证明事实绝对正确。

本技能从 AIGC 文本工作台的项目实践中独立提炼，发布内容为新写说明、工具和虚构样例。项目历史验收与本技能的实际测试分别记录；既有两篇论文示例不代表任意主题的自动检索均已验证。
