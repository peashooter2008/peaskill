# 检查契约与报告解释

## 目标页面适配

配置是一个 UTF-8 JSON 对象，字段值必须是标准 CSS 选择器。每个选择器应唯一匹配元素，不支持 Shadow DOM 与 iframe 内部元素。

| 字段 | 页面元素 | 必需条件 |
| --- | --- | --- |
| `input` | textarea 草稿输入框 | 布局和交互检查都需要 |
| `send` | 明确的发送按钮 | 布局和交互检查都需要 |
| `history` | 自身具有 scrollTop 的记录容器 | 启用交互检查后需要，至少 100px 可滚动历史 |
| `leave` | 离开聊天页面的入口 | 启用交互检查后需要 |
| `back` | 离开后的页面上返回聊天的入口 | 启用交互检查后需要 |

交互约定：手机宽度（不超过 600px）下 Enter 在 textarea 换行；桌面 Enter 行为由应用决定，本工具跳过该项。离开再返回保留草稿；阅读历史和缩小可视区域时不强制跳底；点击发送后，带唯一标记的合成消息必须实际出现在历史容器可见文本中，同时清空输入并滚动到最新消息。若产品有不同的手机 Enter、路由或发送完成行为，调整工具检查后再运行，不能把不适配的失败当成产品缺陷。

## 命令行

```text
node scripts/check_chat_layout.mjs --url URL --config PATH --report PATH
    [--allow-test-actions] [--allow-remote]
    [--browser-path PATH | --channel CHANNEL]
```

路径相对执行命令时的工作目录解析。报告不得覆盖配置。工具不会打印消息内容或读取个人浏览器 profile；报告包含页面路径、选择器、错误摘要和被拦截的 origin，分享报告前仍应检查这些信息。

| 退出码 | 含义 |
| --- | --- |
| `0` | 本次启用的检查通过；默认布局模式仍是 `partial` |
| `1` | 至少一个已执行检查失败，报告保留所有视口结果 |
| `2` | 参数、配置、依赖或浏览器启动出错，检查未完成；不得引用旧报告当作本次结果 |

工具拒绝未知或重复参数。远端许可与交互许可分别指定；`--allow-remote` 不会自动开启发送。默认 Chromium 可通过 Playwright 下载到项目目录；也可使用 `--browser-path` 指向已有浏览器。工具始终创建全新临时浏览器上下文。

## 检查覆盖

固定视口：390×844、320×568、390×440、1366×900。布局模式每个视口检查导航、横向溢出、输入与发送按钮是否完整可见且未被覆盖、页面脚本错误，共 5 项。

交互模式的三个手机视口各增加 Enter 换行、草稿往返、历史阅读位置、缩小视口后的三项布局检查、缩小后的历史位置、消息出现与发送后滚动，共 8 项；桌面视口跳过 Enter，增加另外 7 项。正常样例共 51 项通过、1 项桌面 Enter 跳过，共 52 条检查记录。缩小高度取 `max(260, min(440, 原高度-220))`，用于发现布局随可用高度变化的回归。页面是合成样例时通过只能证明工具及样例的行为，不能代替实际产品适配验收。

JSON 报告提供 `schemaVersion`、`status`（`passed` / `failed` / `partial`）、`actionsEnabled`、`realKeyboardTested`、`skipped`、`summary`（通过、失败、跳过数量）、`blockedOrigins`，以及 `results[].viewport` 与 `results[].checks[]`。每项检查有 `id`、`status`（`passed` / `failed` / `skipped`），失败或跳过时附 `reason`。`target` 隐去查询参数和 fragment。

## 修复时的判断

不要只调整一个机型的固定高度。先确认布局有没有随可视区域变化、flex 子项是否能收缩、消息容器与页面是否分别滚动，再定位异常。草稿应在用户离开聊天时保留，发送成功后清除；历史自动滚动需要区分“用户正在阅读”和“用户主动发送”。这些是决策原则，具体实现按当前应用结构选择。

QQ 等业务绑定属于可选验收：可以离线保存规则；未明确选择人格或联系人时，不应自动启用回复。该项要结合实际业务测试，不包含在本工具上述检查结果内，也不执行真实账号发送。

## 本地回归测试

在已安装依赖和 Chromium 的仓库根目录运行，或将路径改为当前完整技能目录：

```powershell
node --test skills/mobile-chat-regression/tests/test_chat.mjs
```

测试会临时启动绑定 `127.0.0.1` 的 HTTP 服务并自动关闭。它实际运行正常样例，以及故意制造的横向溢出、手机 Enter 不换行、发送时丢弃消息三个负例；丢弃负例仍会清空输入并滚动到底，确保检查器不会仅凭视觉变化误判成功。同时验证远端目标和未知参数在导航前被拒绝。共 3 个测试用例。报告写入仓库 `qa/mobile/`；独立复制技能时会写到技能目录上两级的 `qa/mobile/`，运行前请确认该位置适合存放报告。可通过 `PEASKILL_BROWSER` 环境变量指定测试浏览器可执行文件。
